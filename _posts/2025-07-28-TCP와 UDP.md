## TCP / UDP
TCP(Transmission Control Protocol)와 UDP(User Datagram Protocol)는 전송 계층(Transport Layer)에서 사용되는 프로토콜이다.

|항목|TCP (Transmission Control Protocol)|UDP (User Datagram Protocol)|
|---|---|---|
|**특징**|연결 지향 (connection-oriented)|비연결 지향 (connectionless)|
|**신뢰성**|보장 (순서 보장, 재전송 있음)|보장하지 않음 (순서·손실 무시)|
|**속도**|느림 (오버헤드 있음)|빠름 (오버헤드 적음)|
|**헤더 크기**|20바이트 이상|8바이트|
|**순서 보장**|✅ 순서대로 도착|❌ 순서 바뀔 수 있음|
|**재전송 기능**|✅ 있음 (ACK/NACK)|❌ 없음|
|**흐름 제어**|✅ 있음 (윈도우 크기 등)|❌ 없음|
|**혼잡 제어**|✅ 있음|❌ 없음|
|**전송 단위**|**세그먼트(Segment)**|**데이터그램(Datagram)**|


> - SYN (Synchronize)
> 	- SYNchronize sequence numbers
> 	- 연결 요청을 의미
> 	- **"내가 너랑 통신하고 싶어, 연결 시작할게!"**
> 	- TCP 연결 시, 양쪽이 시퀀스 번호를 맞추기 위한 초기 요청에서 사용됨
> - ACK (Acknowledge)
> 	- 수신 확인 / 응답 신호
> 	- **"너가 보낸거 잘 받았어 !"**
> 	- 대부분의 TCP 통신은 **ACK 없이 진행되지 않음**
> 	- 연결 수립, 데이터 전송, 연결 종료 전부 ACK 있어야 신뢰성 보장
> - FIN (Finish)
> 	- 연결 종료 요청
> 	- **"이제 데이터 다 보냈어. 연결 끊자"**
> 	- TCP는 연결을 양방향으로 각각 종료하므로 FIN도 양쪽에서 각각 보내야 함

## TCP의 내부 동작 구조

##### 1. 3-Way Handshake (연결 수립)

``` markdown
클라이언트 → 서버 : SYN 
서버 → 클라이언트 : SYN + ACK 
클라이언트 → 서버 : ACK
```

- 이 과정을 통해 신뢰성 있는 연결을 사전에 구축하고 데이터 전송 시작
- 연결 수립 시간 소요됨 → 속도는 느림

##### 2. 데이터 전송
- 순서 보장: 순서가 꼬여도 순서대로 재조립
- 수신 확인(ACK): 패킷을 받으면 확인 응답
- 손실 시 재전송: ACK가 오지 않으면 재전송
- 흐름/혼잡 제어: 네트워크 과부하 방지

##### 3. 4-Way Handshake(연결 종료)
```markdown
클라이언트 → 서버 : FIN
서버 → 클라이언트 : ACK
서버 → 클라이언트 : FIN
클라이언트 → 서버 : ACK
```

## UDP 구조
- 3-Way handshake 없음
- 신뢰성 없음
	- 도착 순서도 보장 안 됨
	- 중간에 유실돼도 상관 안 함
- 빠름
	- 별도 연결 없이 바로 전송
- 오버헤드 작음
	- 헤더가 8바이트밖에 안 됨


## 상황별 TCP / UDP
| 상황                  | 사용 프로토콜          | 이유                  |
| ------------------- | ---------------- | ------------------- |
| 웹 브라우징 (HTTP/HTTPS) | **TCP**          | 요청/응답 정확히 보장돼야 함    |
| 파일 전송 (FTP, SFTP)   | **TCP**          | 전송 누락되면 안 됨         |
| 이메일 (SMTP, IMAP)    | **TCP**          | 순서와 정확성 중요          |
| 영상 스트리밍             | **UDP** (or TCP) | 빠른 전송이 우선, 조금 끊겨도 됨 |
| 온라인 게임              | **UDP**          | 딜레이 최소화가 중요, 유실 허용  |
| DNS 요청              | **UDP**          | 빠른 질의응답, 한번에 끝남     |

> HTTP는 내부적으로 TCP를 기반으로 동작한다.
> 하지만 네트워크 프로그래밍 등과 같은 것을 만들 땐 이를 직접 설정 해야 한다.

## Java 예시
##### TCP Client
``` java
Socket socket = new Socket("127.0.0.1", 8080);
OutputStream out = socket.getOutputStream();
out.write("Hello TCP".getBytes());
socket.close();
```

##### TCP Server
```java
ServerSocket serverSocket = new ServerSocket(8080);
Socket client = serverSocket.accept();
InputStream in = client.getInputStream();
byte[] buffer = new byte[1024];
int read = in.read(buffer);
System.out.println(new String(buffer, 0, read));
client.close();
serverSocket.close();
```

##### UDP Client
```java
DatagramSocket socket = new DatagramSocket();
InetAddress address = InetAddress.getByName("127.0.0.1");
byte[] buf = "Hello UDP".getBytes();
DatagramPacket packet = new DatagramPacket(buf, buf.length, address, 8888);
socket.send(packet);
socket.close();
```
##### UDP Server
```java
DatagramSocket socket = new DatagramSocket(8888);
byte[] buf = new byte[1024];
DatagramPacket packet = new DatagramPacket(buf, buf.length);
socket.receive(packet);
String received = new String(packet.getData(), 0, packet.getLength());
System.out.println(received);
socket.close();
```
